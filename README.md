# 仓库简介
这个仓库用于展示课程选题内训方案以及授课型幻灯片。目前仓库主要包含这些结构： README.md，并设有 topic 和 slides 两个文件夹，分别用于存放内训方案以及授课型幻灯片。目前已完成课程选题以及授课型幻灯片整理和上传，已完成了本次纳新任务所要求的仓库内容与文件结构。

# 附加信息
### 你在本次任务中使用了哪些 Git 或 GitHub 功能？
这次任务主要使用了 GitHub 仓库管理功能：
- 创建和管理 GitHub Repository
- 创建 topic、slides 文件夹
- 创建和编辑 Markdown（.md）文件
- 上传 PPT、PDF文件
- 使用 Commit changes 来保存和提交文件修改
- 通过合理的文件夹结构组织内训方案和幻灯片

### 操作过程中遇到了哪些问题？你是如何解决的？
操作过程中，我一开始对 GitHub 和 Git 不太熟悉。例如，我一开始把 topic 和 slides 理解为分支的结构，后来了解到它们是 Repository 中的文件夹。
另外，我也不太清楚如何在已有的 slides 文件夹中继续添加其他文件，以及 Markdown 中的 # 符号有什么作用。通过观看教学视频和实际尝试，我学会了怎么创建文件夹以及上传多个文件。我也学到了 #、## 等等属于 Markdown 的标题语法，而普通字体不需要添加 #。

### 如果将来需要多名教学部成员共同维护这个仓库，你认为应当如何组织文件与修改流程？
我认为首先应该制定统一的文件夹结构、文件命名规则和提交规范，避免仓库内容混乱。在修改内容时，每位成员可以先从 main 分支创建自己的分支 (branch)，在自己的分支中进行修改和测试。完成后，通过 Pull Request把修改给其他成员审核。确认内容没有问题后，再把修改后的分支 merge 到 main 分支。这样可以避免多人直接同时修改 main 分支造成冲突，也可以在合并之前检查修改内容。通过 commit 记录可以追踪每次修改的具体内容和修改者。
